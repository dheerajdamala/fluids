1. Executive Summary & Application Selection

Autonomous navigation in structured and unstructured environments is a foundational challenge in modern robotics, with extensive real-world applications including Automated Guided Vehicles (AGVs) in industrial warehouses (e.g., Amazon Kiva systems), robotic search-and-rescue units, planetary rovers, and pipeline inspection crawlers.

In this project, we designed and implemented a complete intelligent robotic system capable of solving complex 2D mazes and obstacle fields. The system demonstrates how fundamental Artificial Intelligence search techniques can be applied to represent an environment, formulate state spaces, evaluate heuristic constraints, and discover optimal collision-free trajectories.

Core Project Highlights
  • 6 AI Search Algorithms: Full comparative implementation of A* (Manhattan), A* (Euclidean), Breadth-First Search (BFS), Depth-First Search (DFS), Uniform Cost Search (UCS / Dijkstra), and Greedy Best-First Search.
  • Procedural Labyrinth Generation: Randomized depth-first recursive backtracker (Eulerian single-corridor mazes), Prim's randomized minimum spanning tree, obstacle fields (25% and 35%), and dead-end trap configurations.

2. Mathematical Problem Formulation

In accordance with formal AI search agent architecture, the maze navigation problem is formulated as a deterministic, discrete, static, and fully observable state-space search task:

2.1 State Space (S)

The navigation environment is modeled as an N × M orthogonal grid of cells (31 × 31 = 961 discrete cells). A state s ∈ S is defined by the robot's spatial row and column coordinates:

s = (r, c)   where   0 ≤ r < 31,   0 ≤ c < 31,   Grid[r][c] ≠ WALL (1)

2.2 Initial State (S0) & Goal State (G)

  • Initial State (S0): Fixed at the top-left corridor coordinate S0 = (1, 1) with initial orientation angle θ = 0° (pointing East).
  • Goal State (G): Fixed at the bottom-right corridor coordinate G = (29, 29).

2.3 Action Space (A) & Transition Model

From any state s = (r, c), the agent can execute four orthogonal actions:

A = { Up (-1, 0),   Down (+1, 0),   Left (0, -1),   Right (0, +1) } (2)

The deterministic transition function Result(s, a) = s' = (r + Δr, c + Δc) updates the state if and only if s' is within boundaries and does not contain an obstacle.

2.4 Step Cost & Constraints

The transition cost between any two adjacent valid cells is uniform: c(s, a, s') = 1. The total path cost is therefore the total number of steps: g(s) = ∑ c(si-1, ai, si) = k.

2.5 Heuristic Functions & Admissibility Proofs

To guide informed search algorithms, we implemented and evaluated two distinct geometric heuristics:

h1(s) = |r - rG| + |c - cG|   [Manhattan Distance, L1 Norm] (3)
h2(s) = √((r - rG)² + (c - cG)²)   [Euclidean Distance, L2 Norm] (4)

Proof of Admissibility (h(s) ≤ h*(s)): Because orthogonal grid movement restricts each step to Δr + Δc = 1, the shortest possible path without obstacles is exactly the Manhattan distance h1(s). Any physical wall forces the agent to detour, meaning the true minimal cost h*(s) ≥ h1(s). Furthermore, since straight-line distance is always less than or equal to grid distance, h2(s) ≤ h1(s) ≤ h*(s). Both heuristics never overestimate the cost to reach the goal, guaranteeing optimal solution discovery under A*.

Proof of Consistency (Monotonicity): For any cell s and successor s' reachable in 1 step: |h1(s) - h1(s')| ≤ |(r - r')| + |(c - c')| = 1 = c(s, a, s'). Hence, h1(s) ≤ c(s, a, s') + h1(s'), ensuring nodes once closed are never re-opened.

3. AI Search Algorithm Implementations

We implemented six search algorithms divided into uninformed (blind) and informed (heuristic) categories. All algorithms share a common frontier interface and closed-set bookkeeping.

Algorithm Category Frontier Structure Evaluation Function f(n) Completeness Optimality
Breadth-First Search (BFS) Uninformed FIFO Queue f(n) = depth(n) Yes Yes (for uniform step cost)
Depth-First Search (DFS) Uninformed LIFO Stack f(n) = -depth(n) Yes (finite graph) No (highly suboptimal)
Uniform Cost Search (UCS) Uninformed Priority Queue (Min-Heap) f(n) = g(n) Yes Yes
A* Search (Manhattan) Informed Priority Queue (Min-Heap) f(n) = g(n) + h1(n) Yes Yes (Optimal & Efficient)
A* Search (Euclidean) Informed Priority Queue (Min-Heap) f(n) = g(n) + h2(n) Yes Yes
Greedy Best-First Informed Priority Queue (Min-Heap) f(n) = h1(n) Yes (with cycle checking) No

To rigorously assess the algorithms, we executed all 6 implementations on identical test mazes generated under randomized seed conditions. Empirical results were collected across four primary evaluation axes:

4.1 Key Findings & Theoretical Validation

  1. Optimality of A* with Manhattan Heuristic: A* with Manhattan distance demonstrated the highest efficiency among all optimal algorithms, exploring only 91 nodes compared to 479 nodes by BFS—an 81.0% reduction in state space exploration without sacrificing the 26-step minimal path length.
  2. Dominance of Manhattan over Euclidean Distance: Because Manhattan distance strictly dominates Euclidean distance in orthogonal grid space (h1(n) ≥ h2(n)), A* with Manhattan pruned 69 more states than A* with Euclidean (91 vs 160 explored nodes).
  3. DFS Path Inefficiency: DFS generated a path of 60 steps (130.8% longer than optimal) due to its LIFO stack diving deep into dead ends before backtracking.

5. Kinematic 2D Robot Model & User Interface

5.1 Kinematic 2D Robot Model

Unlike static path plotters, our system simulates a physical 2D kinematic robot navigating the discovered route cell-by-cell. The robot representation features:

  • Dynamic Heading & Orientation Angle (θ): Rotates smoothly toward the direction of travel (East 0°, South 90°, West 180°, North 270°).
  • Directional Headlights Conical Beam: Projects an illuminated visibility cone forward, simulating onboard optical LiDAR or ultrasonic proximity sensors.
  • Chassis & Treads: Dual caterpillar tracks that reflect differential-drive steering kinematics.
  • Live Telemetry HUD: Real-time readouts of execution status, total explored nodes, solution length, search latency, and robot step count.
